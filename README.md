# Play Integrity Fix — ROM build for PixelOS 17.0 (branch `seventeen`)

This branch is a fork of [KOWX712/PlayIntegrityFix](https://github.com/KOWX712/PlayIntegrityFix)
(`v4.9-inject-s`) that runs the module inside the ROM, **without root, Magisk or Zygisk**.
It is ported to **PixelOS 17.0** (Android 17) and used by its build for the Lenovo Yoga Tab Plus
(TB520FU, `lapis`). The same app also carries the ROM ports of Specter and TEESimulator.
The module itself (`module/`, `zygisk/`, `webui/`) is kept as upstream; the ROM parts
are in [`rom/`](rom) and [`Android.bp`](Android.bp).

## How it works

- **Loading.** The ROM framework (`PropImitationHooks.loadPifModule()` in
  `frameworks/base`, Apache-2.0) loads `/system_ext/framework/PlayIntegrityFixEntry.jar`
  into `com.google.android.gms.unstable` (DroidGuard) and `com.android.vending`
  and calls `RomEntry.init()`, in place of the Zygisk entry. The ROM's built-in
  spoofing (PIHooks GMS/Play Store spoofing, attestation blocking) is skipped in this
  mode, and used instead whenever the switch is off or the jar is missing.
- **Spoofing.** The same as the module: build fields (`spoofBuild`,
  `spoofVendingBuild`, `spoofVendingSdk`), system properties through the module's
  property virtualizer (`spoofProps`, `libpif_propvirt`), the keystore provider
  (`spoofProvider`, skipped while the ROM has its own keybox) and the signature
  (`spoofSignature`).
- **Scope.** The ROM does not override the system-wide build fingerprint. `spoofProps`
  virtualizes native properties only inside the target processes (GMS, Play Store).
- **Device profile.** Shipped with a built-in Pixel 9 tokay profile
  (`FINGERPRINT`, `MANUFACTURER`, `MODEL`, `SECURITY_PATCH`, `DEVICE_INITIAL_SDK_INT`).
  The user can view, edit, reset to default, or fetch an updated profile from
  GitHub, keeping the chosen options.
- **Auto update.** In place of the module's `autopif_ota.sh`: with the switch on
  (default, `Settings.Global lenovo_pif_auto_update`), the ROM checks
  `module/pif.prop` of `KOWX712/PlayIntegrityFix` (`inject_s`), regenerated by
  its GitHub Action once a day, at boot and every 12 hours, and applies it when it
  changed upstream (keeping the options; Play services and the Play Store restart).
- **Settings.** Settings > Advanced features > Experimental features > *Integrity* has three pages,
  each on by default: **Specter** (one update pass for the other two: device profile, security patch
  source, keybox provider, target apps), **TEESimulator** (keybox, target apps, security patch of the
  attestation service) and **Play Integrity Fix** (main switch, the option switches, the active
  profile, Fetch, View/Edit `pif.prop` and Reset). Every change restarts Play services and the Play
  Store. The pages are translated into the locales of the AOSP Settings app.

Default options (`rom/etc/pif.prop`): `spoofBuild`, `spoofProps`,
`spoofVendingBuild` and `spoofSignature` (the ROM is signed with the test keys) on;
`spoofProvider`, `spoofVendingSdk` and `DEBUG` off.

Not included, because they need root: the module scripts that reset boot and lock state properties
(`post-fs-data.sh`, `service.sh`) and the Zygisk denylist handling. The TrickyStore / TEESimulator
and Specter roles are filled by the ROM's keybox attestation service and the two pages above (see the
[`specter`](https://github.com/wnduddld0513/specter/tree/seventeen) and
[`TEESimulator`](https://github.com/wnduddld0513/TEESimulator/tree/seventeen) forks).

## Requirements on the ROM (PixelOS 17.0 / Android 17)

This is built for **PixelOS 17.0** (Android 17, branch `seventeen`) and needs the matching
changes in the ROM. Without them the package is installed but does nothing.

| Where | What |
| --- | --- |
| `frameworks/base` ([lenovo-sm8650, `seventeen`](https://github.com/lenovo-sm8650/android_frameworks_base/tree/seventeen)) | `PropImitationHooks.loadPifModule()` loads `PlayIntegrityFixEntry.jar` into Google Play services (DroidGuard) and the Play Store while `Settings.Global lenovo_pif_module` is on, and writes the spoofed fields through `Unsafe` |
| `frameworks/base` | `KeyboxAttestationService` (service name `keybox_attestation`), started in `SystemServer` after `AttestationService`; the keystore hook `KeyboxImitationHooks` (called from `KeyStoreSecurityLevel.generateKey` and `KeyStore2.getKeyEntry`) asks it to sign; AIDL in `core/java/android/security/keybox` |
| `device/lenovo/lapis` ([`seventeen`](https://github.com/lenovo-sm8650/android_device_lenovo_lapis/tree/seventeen)) | SELinux: `keybox_attestation_service` type in `sepolicy/private/service.te` and its entry in `service_contexts` |
| `hardware/lenovo` ([`seventeen`](https://github.com/lenovo-sm8650/android_hardware_lenovo/tree/seventeen)) | `custom/custom.mk` adds `PlayIntegrityFixSettings` to `PRODUCT_PACKAGES`; the *Integrity* category of Experimental features opens the three pages |

## Building it into a ROM

1. Add the repository to the local manifest:

   ```xml
   <project name="wnduddld0513/PlayIntegrityFix" path="packages/apps/PlayIntegrityFix" remote="github" revision="seventeen" />
   ```

2. Add the app to the product packages (it pulls in the jar, the native library, `pif.prop` and the
   privapp permissions through `required`):

   ```makefile
   PRODUCT_PACKAGES += PlayIntegrityFixSettings
   ```

3. Build with the usual ROM build (`m` / `brunch`). Things the build relies on:
   - the app is `platform_apis`, signed with the `platform` certificate, runs as `android.uid.system`
     and is installed to `/system_ext/priv-app` (`system_ext_specific`, `privileged`);
   - `privapp-permissions-pif.xml` must be installed, or the privileged permissions
     (`WRITE_SECURE_SETTINGS`, `FORCE_STOP_PACKAGES`, `CLEAR_APP_USER_DATA`) are refused at boot;
   - `libpif_propvirt` is C++20 and compiles the module's `pif_config.cpp` and `property_virtualizer.cpp`
     unmodified;
   - the entry jar is installed to `/system_ext/framework/PlayIntegrityFixEntry.jar`;
   - the pages are exported with `WRITE_SECURE_SETTINGS` as permission, so only the system uid (Settings)
     can open them.

No root, Magisk, KernelSU, Zygisk, init service or ZIP is involved; it works the same on a device with or
without root.

## Upstream module: Play Integrity Fix

This module tries to fix Play Integrity verdicts to get a valid attestation.

### NOTE

This module is not made to hide root, nor to avoid detections in other apps. It only serves to pass Device verdict in the Play Integrity tests and certify your device.

### Tutorial

You will need root and Zygisk. Enable Magisk's built-in Zygisk or use [ZygiskNext](https://github.com/Dr-TSNG/ZygiskNext) / [NeoZygisk](https://github.com/JingMatrix/NeoZygisk) / [ReZygisk](https://github.com/PerformanC/ReZygisk).

### Options

- **spoofBuild**: spoof fingerprint field, enabled by default.
- **spoofProvider**: custom keystore provider, enable when not using [TrickyStore](https://github.com/5ec1cff/TrickyStore) or [TEESimulator](https://github.com/JingMatrix/TEESimulator).
- **spoofProps**: spoof prop when gms read from system prop, enable when not using [TrickyStore](https://github.com/5ec1cff/TrickyStore) or [TEESimulator](https://github.com/JingMatrix/TEESimulator).
- **spoofSignature**: spoof rom signature, enable when your rom is signed by testkey. You can check your rom signature by running this command in terminal.
  ```sh
  unzip -l /system/etc/security/otacerts.zip | grep -oE "testkey|releasekey"
  ```
- **spoofVendingSdk**: spoof sdk version to 32 to Play Store if your device runs Android 13 or higher, this option will not take effect if your device is running Android 12 or lower.
  - Known issue: 
    - Back gesture/nav button from within the Play Store exits directly to homescreen for all
    - Blank account sign-in status and broken app updates for ROMs A14+
    - Incorrect app variants may be served for all
    - Full Play Store crashes for some setups
  - pixel_beta fingerprint can no longer get device verdict even on legacy check, so enabling this option won't help you to get device verdict anymore.

### Variety

- **inject-vending**: Based on the official inject branch, with the added spoofVendingSdk option.
- **inject-manual**: Based on inject-vending, with auto config (detect TrickyStore and ROM signature) removed.
- **inject-s**: Based on inject-manual, lightweight since it dropped the JSON format (pif.json -> pif.prop).

> [!NOTE]
> **inject-vending** and **inject-manual** branches are discontinued, but the branches will not be removed.

> [!WARNING]
> Do not use third-party tools to fetch fingerprints to avoid conflicts.
> The WebUI provides full control for configurable options.
